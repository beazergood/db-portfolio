Portfolio Refresh

davebeazer.dev hasn't had its canonical content touched in years. The April Fools build was the first change since the rebuild. This is the second — and the bigger one. A quieter, more deliberate surface that reflects who the project is now.

Status: spec Owner: Dave Branch: tbd Started: 2026-04-27

The why

The current page names specific employers and clients. That doesn't reflect the direction any more — work is described by kind, not by brand. Beyond the copy, the structure itself is due a re-think: a static "about me" doesn't suit someone whose work lives mostly in projects.

The replacement keeps the calm surface of the existing site and reuses the same hues and typography. It's an evolution, not a redesign — that comes later (or doesn't), as a separate question.

What it keeps · what it changes

Keeps

  • Calm surface — no popups, no banners, no urgency.
  • Mint / purple / melon palette and the hand-drawn waves.
  • One-page spine with depth that grows behind clicks.
  • Loads instantly on patchy mobile.
  • Paytone One headings, Inter body.

Changes

  • No named clients or employers in copy.
  • "About me" prose replaced by dynamic project facets.
  • Tagline refreshed without the "for organisations including…" tail.
  • Skills and approach blocks audited — keep what still rings true, drop what doesn't.
  • Contact list audited and pruned.

Open questions

Surfaced visibly. The answers will land as the work proceeds.

  1. What are the dynamic facets? Project cards that surface different work each visit? Cards that pull from the wiki? Live data from a project? No answer yet.
  2. Does the redesign-retro PoC fit anywhere? It was a visual experiment, parked. It may donate specific elements but isn't the canonical direction.
  3. Is "no one-pager" actually true? Or is the one-pager fine if the depth lives behind clicks rather than scrolls?
  4. What replaces the PL/Pexip line specifically? Need a verbal model for describing work without brands.
  5. Where does the wiki feed in? Could project cards be generated from feature specs? The spec→portfolio pipeline could be its own facet.
